# 前端重建

两端的前端各自换成现成的 UI 框架，不再手写组件。

| | 现在 | 目标 |
| --- | --- | --- |
| 云端控制台 | Next.js + Tailwind，组件自己写 | Next.js + Tailwind + **shadcn/ui** |
| 边缘面板 | 单文件 HTML + Alpine + 836 行手写 CSS | **Leptos + WASM + Thaw UI** |

两端**不共用**设计系统。这是有意的：它们的约束不一样，硬凑一套会让两边都别扭。

分阶段的做法各自写在：

- [cloud-shadcn.md](cloud-shadcn.md)
- [edge-leptos.md](edge-leptos.md)

## 已经定下的决定

**云端用 shadcn 的默认主题**，不是把 shadcn 的语义变量映射到现有配色上。

代价要写清楚：现有那套配色是量出来的——32 组配对的对比度、按比例构建的表面梯度（暗色 1.0735 / 1.0643 / 1.0833），还记录着一次事故：最淡的文字层在两个主题里都不可读（暗色最差 3.200，亮色 2.810），而它当时承载着每一个列标题、每一个导航分组标签、页脚和所有提示。换主题等于放弃这些结论重新开始。

**230 个钉住设计的测试全部退休**，不引入能跑 `.tsx` 的测试运行器。

shadcn 的类名写在 `.tsx` 里，而这个 app 测不了 `.tsx`——没有 jsdom、没有 testing-library、没有 vitest/jest，`package.json` 的 test 脚本是手写文件列表。`lib/tokens.ts` 的文件头解释过这个拆分存在的唯一理由就是可测性。

退休的包括 **13 个对比度守卫**。那是无障碍硬指标，不是审美偏好；退休之后配色改错只能靠肉眼发现。这一条被明确权衡过并接受。

⚠️ 但保留下来的守卫里有一条**不能退休**：「每个用到的类必须真的产出 CSS」。它在
迁移过程中连续抓到四次静默失效——透明度、间距、环宽、布局刻度——其中一次会让
**焦点环整体隐形**。Tailwind 对刻度外的值不报错，只是不生成规则，而类名照样写
在 HTML 上。

| 文件 | 数量 |
| --- | --- |
| `lib/tokens.test.ts` | 155 |
| `lib/pwa.test.ts` | 57 |
| `lib/contrast.test.ts` | 13 |
| `lib/palette-drift.test.ts` | 5 |

**边缘端的 WASM 在边缘机上构建**，不提交产物进仓库。仓库保持没有二进制。

**信息密度要压。** shadcn 和 Thaw 的默认间距都偏宽松，而这两个界面都是要在一屏里塞下很多东西的运维界面。做法是**改库的默认尺寸，集中改一次**，不是逐个组件手写覆盖——那样等于又回到手写。

## 一个会消失的东西

`scripts/check-token-parity.cjs`：CI 里比对两端 token 声明的守卫，现在是 `PARITY OK`（45 个共享名字，32 个完全一致，13 个归一化后一致）。

它存在的前提是"边缘面板逐个手抄云端的 token 名字和值"——`lib/tokens.ts` 的文件头写着「**在这里改一个 token 名字，等于改了另一个仓库**」。两端各自换框架之后这个前提不成立了，这个守卫应该退休。

⚠️ 退休它意味着两端的视觉从此**各走各的**。这是这次重建的直接后果，不是疏忽。

## 顺序

云端先做，边缘端后做。两件事互相独立，没有依赖。

云端完全在工作站上，不依赖边缘机。边缘机今天多次掉线，而且需要先修 DNS、装 rustup、装 trunk 才能开工——见 `edge-leptos.md` 的「前置条件」。
