## 已经定下的决定

**云端用 shadcn 的默认主题**，不是把 shadcn 的语义变量映射到现有配色上。

⚠️ 有三个例外，是量出来之后回填的：`--muted-foreground`、`--destructive`、
`--destructive-foreground` 在两个主题里都指回本项目推导过的值（`--fg-faint` /
`--bad` / `--bad-ink`）。shadcn 的默认值是照它自己那两层表面调的，放到这个控制台
的四层梯子上不合格——`text-destructive` 暗色只有 2.08:1。所以是「整体采纳，个别
回填」，不是「全盘照抄」。

代价当时写清楚过：那套配色曾经是量出来的——32 组配对的对比度、按比例构建的表面
梯度（暗色 1.0735 / 1.0643 / 1.0833），还记录着一次事故：最淡的文字层在两个主题
里都不可读（暗色最差 3.200，亮色 2.810），而它当时承载着每一个列标题、每一个导航
分组标签、页脚和所有提示。**这套配色已经在 9a47170 删除**，画布从 #010102 变成
#09090b。但上面那三个 token 说明：被放弃的是配色表，不是那些结论——三条推导过的
值最后原样回到了新主题里。

**测试的处理：原计划「230 个钉住设计的测试全部退休」，实际只退休了 29 个。**

原因见 cloud-shadcn.md 的「一个必须做的修正」：`tokens.test.ts` 的 155 条里有 25
条是**安全测试**，它们靠读源码文本工作，从来就不需要 `.tsx` 测试运行器。「不加
测试运行器」和「保住安全测试」并不冲突，所以改成**纯设计的退休，安全的更新**。

⚠️ 前提本身没变，仍然成立：shadcn 的类名写在 `.tsx` 里，而这个 app 测不了
`.tsx`——没有 jsdom、没有 testing-library、没有 vitest/jest，`package.json` 的
test 脚本是手写文件列表。变的只是从这个前提推出的结论。

🔴 **「退休 13 个对比度守卫」这句话是错的，它们一条都没退休。**

这份文档原先写着这 13 条被作为取舍主动退休，代价是「配色改错只能靠肉眼发现」。
事实是它们全程都在跑。真正出问题的是**它们的取值口**：整族守卫读的是
`COLOR_TOKENS`，而 shadcn 的语义色直接写在 `globals.css` 里，从来没进过那张表——
**守卫活着，但对半套调色板是瞎的**。换主题带进来的四个对比度缺陷因此全部漏过。

8b94949 修的就是这个：取值口改成解析 `globals.css` + 扫 `.tsx` 源码（解析器抽成
`lib/palette-source.ts`，只此一份），角色表认得 shadcn 的名字，另加第 14 条守卫
「同一条规则里一个自定义属性只能声明一次」。

⚠️ 还有一条守卫**不能退休**：「每个用到的类必须真的产出 CSS」。它在迁移过程中
连续抓到四次静默失效——透明度、间距、环宽、布局刻度——其中一次会让**焦点环整体
隐形**。Tailwind 对刻度外的值不报错，只是不生成规则，而类名照样写在 HTML 上。

但它**必要而不充分**：它看不见「同一条规则里一个变量声明了两次」这类事故——那些
类确实产出了 CSS，坏的是变量的运行时取值。所以才有上面那条配套守卫。

## 一个已经消失的东西

`scripts/check-token-parity.cjs`：CI 里比对两端 token 声明的守卫，**已于
2026-09-02（d8dc5e6）退休并删除**。

退休前它一直报 `PARITY OK`（45 个共享名字，32 个完全一致，13 个归一化后一致）；
最后一次它报的是「`--secondary` 只在云端声明」——它说得对，只是它守的那个约定已经
作废。

它存在的前提是「边缘面板逐个手抄云端的 token 名字和值」。两端各自换框架之后这个
前提不成立了。退休的记录连同后果写在 `.github/workflows/ci.yml:43-51`。

⚠️ **两端的视觉已经分开了**，不是将来会分开：云端画布 #09090b，边缘面板仍是
#010102，并且仍然声明着云端已经删除的那 16 个 token。这是这次重建的直接后果，
不是疏忽。

🔴 两处遗留的错误说明，还没改：`apps/console/lib/tokens.ts` 的文件头至今写着
「在这里改一个 token 名字，等于改了另一个仓库」；边缘面板 CSS 里「和云端 token
块同名同值」那句注释现在也是错的。
